# Helix editing

The [user manual](../helix-mode.md) records the delivered subset. Helix owns an independent reducer in `input::helix`; it does not translate commands to Vim sequences. The exclusive `ModalInput` session and read-only suspension live in `App` (see [input.md](input.md)). The UI borrows that typed session to derive badge text and color together; the cursor reuses the same style. Display labels do not drive style decisions.

## Support boundary

The initial handler implements the basic single-selection workflow and the exact key subset in the [manual](../helix-mode.md#scope-and-limitations). It has no match/text-object/surround state, regex/multiselection engine, leader menu or native Helix keymap loader. Absence of those features is separate from the future multiple-selection model: delimiter text objects could be added with one selection in another change.

`input::helix::feed` consumes an unknown ordinary key individually and resets its pending count. It does not recognize `m`, `Space`, `[`/`]` or `z`/`Z` as prefix modes, so the following keys retain their normal meaning. In particular, `mi(`/`ma"` enter Insert and insert a delimiter, while `md"` deletes the current selection. An implemented `g` prefix consumes an unsupported following key as one pending sequence; `:` captures and validates a whole command. These are distinct paths, not a general unsupported-sequence recognizer.

Ctrl/Super and most Alt chords pass through to application bindings outside a prompt; only `Alt+;` is a Helix Alt command in Normal/Select. `input::helix::is_app_shortcut` is the common ownership rule used by the reducer and the global-key hints, including function/page keys. Prompt capture, Escape and ordinary Insert delegation run before that rule; the hints deliberately list global shortcuts rather than ordinary Insert text bindings. The user-facing omissions table must describe missing native behavior rather than promise every unsupported chord is a no-op. The embedded-manual scenario exercises the `mi(`/`ma"`/`md"` examples against real App dispatch. A future text-object implementation must update those examples, the manual and its acceptance assertions together.

## Selection geometry

`EditorState::selection` is the sole persistent document selection, an oriented half-open pair of **character** offsets. `editor::helix_ops::set_selection` snaps outward to grapheme boundaries and derives the cursor: the last grapheme before the high boundary for forward selections, the low boundary for backward selections. Collapse and flip use this same derivation. Empty documents keep an empty selection; a nonempty EOF collapses backward onto the last grapheme. Helix never uses Vim's inclusive Visual widening. Boundary snapping uses `GraphemeCursor` over rope chunks, requesting preceding context when Unicode rules need it, without copying or collecting the source line. Very long combining clusters and regional-indicator runs can still require proportional context.

Normal destination motions replace the range; Select preserves the fixed grapheme while moving the other end. Point destinations and search matches share `helix_ops::select_range`: points include their target grapheme, while matches include the whole normalized range even when it overlaps the fixed grapheme. Word motions select a path using the shared word classes, with Normal retaining the final motion range (`2w`) and Select retaining its original anchor (`v2w`). Navigation calls existing editor actions for configured visual/source vertical movement, preserving the preferred column across normalization. Direct source-line jumps clamp without iterating the requested number of lines. Counts saturate on input and repeated motions are capped at 9999.

`x/X` derive source-line bounds from the half-open range, so a final newline belongs to the preceding line. A session flag records the explicitly linewise nature of a selection for the internal register. Motions and external cursor/selection edits invalidate that flag; yanking keeps it. The flag is metadata, never permission to widen an edit beyond its highlight. Character finds scan grapheme boundaries across source lines, clamped by the rendered cell scope.

## Selection actions and tables

`helix_ops::apply_operator` is the selection action entry point for `d/c/y`. Read-only refusal precedes mutation. The exact normalized highlighted range reaches the shared table range guard before a delete/change; a refusal preserves text, register and history. A yank restores the cursor and selection after the shared operator's flash. See [vim-tables.md](vim-tables.md) for the existing guard's byte/character conversion contract.

The reducer stores one `HelixPending` prefix (`None`, `G`, `Find(char)` or `Replace`) and its text/linewise register, not a second document selection. The optional count stays independent so sequences such as `2g` and `2f` can retain both; input saturates at `u32::MAX`, while repeated operations clamp at 9999. Numeric line jumps retain the raw count and clamp to the document. `reset_pending` clears both prefix and count. External editor actions and pointer changes reconcile the sole selection; document replacement reconstructs it rather than clamping an old range onto new text.

## Future multiple selections

This version has one selection. A separate change must add multiple selections and simultaneous editing: an ordered collection with a primary selection, overlap/merge rules, grapheme invariants, cursor creation/removal and generation from search. Resolve all ranges against one buffer version, validate every range before the first mutation, remap positions after edits, and record one undo transaction for the whole action. Rendering, scrolling, clipboard, search, mouse and table guards must consume every range. No collection or pretend one-element multiselection loop belongs in this version.

## Mutation, paste and history

`helix_ops::actions::replace_range` validates the normalized character span and the **final payload**, converts once to bytes for the shared structural range guard, and validates cell versus complete-row insertion before writing. Linewise paste computes the actual destination and separator first; metadata alone never authorizes a replacement inside a cell. The same entry serves reducer edits, terminal/clipboard paste and global range actions in `app::helix_actions`. Formatting uses `edit_ops::wrap_plan`; image/link snippets use the shared snippet planner. Both expose the complete proposed delta to Helix's guard while retaining Default's existing rules. Plain Tab insertion uses the same replacement guard; table navigation and list indentation retain their structural helpers.

Selection transformations use the exhaustive `actions::Transform` enum; `Replace(char)` carries its required character. Helix operations return `HelixError`, retaining the shared `TableBreak` and `SearchError` reasons as typed values. Only the reducer and App turn those errors into display text; guard order and refusal messages remain unchanged.

A conservative check of the resulting line's first character skips whole-document reconstruction for edits outside possible list markers or indented continuations. Ordered-list normalization is composed on a string through existing `list_edit` helpers; `EditDelta::diff` collapses the result into one character-offset delta. `History::break_group` separates each range action from its neighbors. Default/Vim and ordinary Insert retain the usual contiguous merging. Undo/redo reconstruct the selection from the restored cursor rather than keeping stale offsets. An empty cell is the other valid empty selection besides an empty buffer: normalization leaves its insertion slot alone, without selecting padding or delimiters.

`helix_ops::insert` resolves `i/a` from normalized bounds, `I/A` from the moving-end source line or rendered cell, and `o/O` from the outer lines touched by the selection. Structural opens use existing table/list helpers; opening before the first list item inserts its marker through the common replacement path. Insert then delegates events to the standard editor. The register is session-local text plus a linewise bit; the clipboard port and kill-ring remain separate.

## Prompts, search and file commands

Helix uses `CmdLineState` and the existing Vim command-line text editing helpers without adopting Vim's command language or incsearch/substitute preview. Its open prompt is one `Option<HelixPrompt>` pairing that line with a required `PromptOrigin`; opening, submission, cancellation and suspension change the pair together. `PromptOrigin` is a transient cancellation snapshot (selection, cursor, scroll and buffer version), never a second ongoing editing selection. `HelixState::cancel_prompt` consumes the pair and restores the snapshot only on the same buffer version when the caller allows restoration. App capture forbids restoration in read-only, Diff and replacement-search contexts; Escape retains the ordinary editable-prompt behavior. Document replacement/suspension drops it. The prompt captures Ctrl chords before ordinary passthrough; App resolves only the configured Paste action ahead of the reducer. Both paste origins use `cmdline::paste_str_bounded`: transform first, retain at most the remaining capacity, keep escape pairs intact and leave the existing draft's tail alone. Typing is bounded by the same 1024-character cap.

`helix_ops::search` uses `SearchState`'s literal/smartcase/escape matching and freshness check. It converts the focused match's byte range once and normalizes the resulting selection. `n/N` skip the current match even though Helix's cursor is on its final grapheme; they move forward/backward respectively. This follows the [official command directions](https://github.com/helix-editor/helix/blob/master/helix-term/src/commands.rs), while Select deliberately extends the single range instead of adding another selection.

The `:` parser accepts only six exact trimmed names and returns file intents. No shell, path parser or process launcher is called. `App::save_from_helix` calls the usual save funnel, or passes an `AfterSave` continuation to Save As/overwrite confirmation; only successful completion sets `should_quit`. `q` routes through the existing dirty-quit guard. No filename is written by the reducer.

## Capture and external changes

The application cancels pending sequences whenever a capturing context takes over. Prompt snapshots are dropped on document replacement and only restored on cancellation against the same version. `sync_helix_after_external` keeps a new mouse/editor selection when its active endpoint agrees with the cursor; otherwise it constructs the cursor's grapheme. This matters when navigation restores a cursor after the new document's initial selection was made. No selection from a previous document survives.

Batch eligibility is resampled after each key and excludes Helix outside Insert and any prompt/capturing context. A modal interrupts the batch and the unhandled suffix is requeued unchanged. Read-only manual navigation parks the session, preserves its register, refuses edits/save/paste and resumes in Normal on return. The application search modal uses the same single whole-match selection when it is navigate-only; replacement search continues to own input. See [input.md](input.md).
